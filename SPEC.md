# SPEC: кириллический поиск в мегабазе + фидбек «ничего не найдено»

## Контекст и диагноз

Прод https://tts-chess-megabase.iosurun.workers.dev/app/ жаловоба «не работает».
Полная headless-диагностика (Playwright, /tmp/opencode/pw) показала: клиентский
рантайм здоров — 0 console errors, ассеты 200, IndexedDB-кеш работает, доска
рендерит 32+ `<piece>`. Реальный баг воспроизводится так:

- пользователь ищет «Карлсен» (кириллицей, как подсказывает сам плейсхолдер
  «Морозевич, Карлсен, Билль…»);
- `searchGames` делает обычный substring-поиск: в индексе 115 142 партии, имена
  хранятся латиницей ("Carlsen, Magnus") → **0 результатов**;
- UI не показывает никакого состояния «не найдено» — пустая панель без фидбека.

Для русскоязычного пользователя это выглядит как «сайт не работает».

Замер на реальном meta.json (`/tmp/opencode/pw/bench-final.js`): после редукции
обеих сторон «Карлсен» находит 11130 партий, «Морозевич» 3454, «Аронян» 7959,
«Гукаш»/Gukesh 378 и т.д. Все 13 тестовых пар кириллица↔латиница дают
идентичные редуцированные формы.

## Цель

1. Кириллический запрос находит латинские имена из индекса (фонетическая
   редукция обеих сторон).
2. Пустой результат виден пользователю (empty state), а не молчаливая пустота.
3. Латинский путь поиска и всё остальное поведение — без изменений (минимальный дифф).

## Архитектура фикса

`searchGames` в `apps/web/src/data/library.ts` получает второй, «редуцированный»
путь, включаемый только если в запросе есть кириллица:

- **pass 1 — транслитерация (только запрос):** кириллица → латиница по таблице
  (`щ→shch`, `ж→zh`, `х→kh`, `ц→ts`, `ч→ch`, `ш→sh`, `й→y`, `ю→yu`, `я→ya`, …).
- **pass 2 — фонетическая редукция (обе стороны):** однопроходный switch по
  строке, сворачивает диграфы и одиночные буквы так, чтобы транслит и
  оригинальная латиница давали одинаковую форму: `shch/sch→s`, `zh→z`,
  `kh→k`, `ts/tz→k`, `ch/ck/c→k`, `sh→s`, `ja/ya/ia→a`, `ju/yu→u`,
  `j/y→i`, `iy→i`, `x→ks`, `w→v`; пробел, запятая, дефис, цифры — без изменений.
  Пример: «Карлсен» → `karlsen` = reduce("Carlsen") → `karlsen`.
- **Редуцированные строки индекса** (`${w} ${b} ${e}`.toLowerCase() → reduce)
  строятся лениво, при первом кириллическом запросе (~600 мс на 115k строк,
  замерено), и кешируются на уровне модуля, привязанно к identity массива rows.
- Скоринг и сортировка в редуцированном пути — те же, что в существующем
  (idx === 0 / после пробела-запятой → 2, иначе 1; сортировка по дате и score).

## Задачи

### T1 — `apps/web/src/data/library.ts`

1. Добавить `const CYR: Record<string, string>` — таблицу транслитерации
   (строчные а-я + ё; Ё/заглавные не нужны — перед транслитом всегда toLowerCase).
2. Добавить функцию `reduceLatin(src: string): string` — однопроходная свёртка
   (switch по текущему символу, от длинных диграфов к коротким). Референс-код
   (проверен бенчем на полном meta.json, 581 мс precompute):

   ```ts
   function reduceLatin(src: string): string {
     let out = "";
     let i = 0;
     const n = src.length;
     while (i < n) {
       switch (src[i]) {
         case "s":
           if (src.startsWith("shch", i)) { out += "s"; i += 4; }
           else if (src.startsWith("sch", i)) { out += "s"; i += 3; }
           else if (src.startsWith("sh", i)) { out += "s"; i += 2; }
           else { out += "s"; i++; }
           break;
         case "z":
           if (src.startsWith("zh", i)) { out += "z"; i += 2; } else { out += "z"; i++; }
           break;
         case "k":
           if (src.startsWith("kh", i)) { out += "k"; i += 2; } else { out += "k"; i++; }
           break;
         case "t":
           if (src.startsWith("ts", i) || src.startsWith("tz", i)) { out += "k"; i += 2; } else { out += "t"; i++; }
           break;
         case "c":
           if (src.startsWith("ch", i) || src.startsWith("ck", i)) { out += "k"; i += 2; } else { out += "k"; i++; }
           break;
         case "j":
           if (src.startsWith("ja", i)) { out += "a"; i += 2; }
           else if (src.startsWith("ju", i)) { out += "u"; i += 2; }
           else { out += "i"; i++; }
           break;
         case "y":
           if (src.startsWith("ya", i)) { out += "a"; i += 2; }
           else if (src.startsWith("yu", i)) { out += "u"; i += 2; }
           else { out += "i"; i++; }
           break;
         case "i":
           if (src.startsWith("iy", i)) { out += "i"; i += 2; }
           else if (src.startsWith("ia", i)) { out += "a"; i += 2; }
           else { out += "i"; i++; }
           break;
         case "x": out += "ks"; i++; break;
         case "w": out += "v"; i++; break;
         default: out += src[i]; i++;
       }
     }
     return out;
   }
   ```

   ВАЖНО: в бенче был баг `i += 5` для "shch" (4 символа, не 5) — в коде выше
   уже исправлено на `i += 4`.

3. Добавить module-level кеш:
   `let reducedCache: { rows: MetaRow[]; hays: string[] } | null = null;`
   и функцию `reducedHays(rows: MetaRow[]): string[]` — вернуть из кеша, либо
   построить `rows.map(r => reduceLatin(`${r.w} ${r.b} ${r.e}`.toLowerCase()))`
   и закешировать.
4. В `searchGames`: если `/[а-яё]/.test(q)` (q уже lowercased/trimmed) —
   редуцированный путь: `nq = reduceLatin(q.replace(/[а-яё]/g, ch => CYR[ch] ?? ch))`,
   terms из nq, поиск по `reducedHays(rows)` с тем же скорингом/сортировкой/limit.
   Иначе — существующий код без единого изменения (латинский путь байт-в-байт
   тот же).

## Критерии приёмки

- `pnpm --filter web build` проходит без ошибок типов.
- Node-проверка собранной логики (экспорт searchGames, скомпилированный tsc):
  «Карлсен» → >10000 hits; «Морозевич» → >3000; «Гукеш» > 300; «Аронян» > 7000;
  «Carlsen» → 60 (limit) — регресс латиницы не сломан; «Билль» → >0;
  запрос из одних «ъ/ь» → 0 (guard от пустых термов после транслита).
- Повторный headless-QA на проде после деплоя (делает архитектор, не воркер):
  ввод «Карлсен» → появляются строки результатов; клик по первой → `.board piece`
  ≥ 32; ввод «ыыыы» → виден empty-state текст; console без ошибок.

## Non-goals / известные ограничения

- Не трогать: loadMeta, fetchGameBody, IndexedDB, ChessBoard, деплой-конфиг.
- Не добавлять новые зависимости.
- Транслит фонетический, не «правильный»: известные потери — «Раджабов»
  (radzabov vs Radjabov→radabov), «Дин Лижэнь» (lizen vs liren). Фикс по ним —
  отдельная тема, если понадобится.
- Латинские опечатки/фонетика («Karlsen» вместо «Carlsen») НЕ матчатся —
  латинский путь сознательно не меняется (минимальный дифф). Возможное
  будущее улучшение — fallback на редуцированный поиск при 0 hits.
- Первый кириллический поиск платит ~600 мс precompute (один раз за сессию).

# DOCS — chess-megabase

Веб-приложение для поиска по шахматной мегабазе (~115 142 партий): поиск по
игрокам/турнирам, просмотр партий на интерактивной доске.

Прод: https://tts-chess-megabase.iosurun.workers.dev/app/

## Запуск локально

```bash
pnpm install          # один раз
pnpm --filter web dev # дев-сервер Astro (apps/web)
pnpm --filter web build  # прод-сборка в apps/web/dist
pnpm --filter web typecheck  # tsc -p tsconfig.check.json (проверка типов)
```

Требования: Node >= 20, pnpm 10 (workspace: `apps/web` + пакеты `packages/*`).

## Деплой

Cloudflare Workers, конфиг `wrangler.jsonc` в корне:

```bash
npx wrangler deploy
```

Статика (включая `apps/web/dist` и `apps/web/public/data/meta.json`) отдаётся
воркером; деплой не трогает данные индекса — он пересобирается только если
меняется источник мегабазы.

## Архитектура

- **Фронт:** Astro 7 (static output) + Solid.js (`LibraryApp.tsx` — весь UI
  поиска и доски), UnoCSS, шахматная доска на собственном рендере (`ChessBoard`).
- **Индекс:** `apps/web/public/data/meta.json` — компактный JSON на 115k партий
  (~15 МБ, ~2 МБ gzip). Ключи строк: `i` (id), `w`/`b` (белые/чёрные), `r`
  (результат), `d` (дата AAAA.ММ.ДД), `e` (турнир), `eco`, `p` (полуходы).
- **Кеш индекса:** IndexedDB (`chess-megabase` → store `meta`) по ETag: при
  загрузке делается HEAD-запрос, если ETag совпал с кешем — индекс читается
  офлайн из IDB, иначе качается по сети и кладётся в кеш.
- **Тела партий:** PGN тянутся с спящего Sailbox-а (`BOX_URL` в
  `apps/web/src/data/library.ts`, wake-on-demand) с ретраями до ~20 попыток
  (бокс просыпается десятки секунд); статус пробуждения показывается в UI.
- **Поиск** (`searchGames` в `apps/web/src/data/library.ts`), два пути:
  - **Латинский (исходный):** substring по `w b e` в нижнем регистре; скоринг:
    совпадение в начале строки / после пробела или запятой → 2, иначе → 1;
    сортировка по дате (новые сверху), потом по score; лимит результатов (в UI
    — 60, с debounce 180 мс).
  - **Кириллический:** включается, если в запросе есть `[а-яё]`. Pass 1 —
    транслит запроса по таблице `CYR` (щ→shch, ж→zh, х→kh, ц→ts, ч→ch, ш→sh,
    й→y, ю→yu, я→ya, ъ/ь→"" и т.д.). Pass 2 — фонетическая редукция `reduceLatin`
    **обеих** сторон (запроса и хейстеков): свёртка диграфов/букв так, чтобы
    транслит и оригинальная латиница дали одинаковую форму
    (shch/sch→s, zh→z, kh→k, ts/tz→k, ch/ck/c→k, sh→s, ja/ya/ia→a, ju/yu→u,
    j/y→i, iy→i, x→ks, w→v). Пример: «Карлсен» → `karlsen` = reduce("Carlsen").
    Редуцированные хейстеки (`${w} ${b} ${e}`.toLowerCase() → reduce) строятся
    лениво при первом кириллическом запросе и кешируются на уровне модуля
    (`reducedCache`, привязан к identity массива rows). Скоринг/сортировка/лимит
    — те же, что в латинском пути. Запрос, состоящий из одних «ъ/ь» (после
    транслита — пустые термы), возвращает 0 результатов (guard).
- **Empty state:** если запрос непуст и ничего не нашлось, в панели «Партии»
  показывается «Ничего не найдено. Попробуйте другую транскрипцию имени…».

## Известные ограничения

- Первый кириллический поиск платит ~600 мс за построение редуцированного
  индекса (115k строк, один раз за сессию/перезагрузку страницы).
- Фонетика не идеальна: «Раджабов» (radzabov vs Radjabov→radabov) и
  «Дин Лижэнь» (lizen vs liren) не матчатся.
- Латинские опечатки не прощаются: «Karlsen» вместо «Carlsen» не найдётся —
  латинский путь substring-точный и сознательно не менялся. Возможное будущее
  улучшение — fallback на редуцированный поиск при 0 hits.
- Украинские/белорусские буквы (і, ї, є, ґ, ў) не входят в таблицу транслита —
  запросы с ними ищутся только по латинской части.
- Тела партий доступны, только пока Sailbox-библиотека проснулась; после долгого
  простоя первая загрузка партии занимает время на пробуждение.
